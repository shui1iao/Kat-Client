# Build inputs: Kat-Client v0.2.3 / Windows Core v0.8.2

The public tag, Kat-Source.zip and Kat-Source.tar.gz carry the reviewed application/core source, generated frontend assets, dependency locks, tests and third-party notices. SOURCE-MANIFEST.json excludes only its two self-referential identity files and non-source build/cache directories. BUILD-IDENTITY.json binds this source to the actual release binaries.

Prerequisites: Linux amd64, Go 1.26.9, Node/npm with app/package-lock.json, Rust/cargo-xwin, a Windows SDK/MSVC sysroot and the Cargo.lock dependency cache, Python3, cryptography and dpkg-deb. Prepare dependencies before offline building; inside app run npm ci as appropriate. These third-party compiler/SDK dependencies and the issuer private key are not bundled.

Extract the source and Kat-Build-Support.tar.gz. Set KAT_SOURCE_ROOT to the absolute source root and KAT_TOOLCHAIN_ENV to your prepared toolchain environment, then run build-support/build-release.sh. The driver builds the frontend, the desktop-tagged core/cmd/kat-client-core Windows entry and four Rust hosts, and then builds kat-install-helper bound to the exact service/peer hashes. Versions are Client0.2.3/Core0.8.2, sequence1794300003. It does not use the removed core/cmd/kat server entry. It stops after producing six binaries and their hashes; it does not claim to have issued an installable signed package.

Official package assembly is an issuer-only step: create the exact six-component kat-package-auth.json with current peer hashes and core source fingerprint, sign it using the authorized original Ed25519 issuer key, and generate BUILD-IDENTITY.json for those same bytes. Populate the roles from app/src-tauri/src/installer_files.rs using the compiled executables, source distribution notices, core/docs/client/kat-client.example.yaml and YAML.md, and app/src-tauri/vendor/network. The two fixed NSIS 3.11 Debian packages are in build-support; extract them into the task-local integration-evidence/comprehensive-20261029/native/setup-installer/toolchain/nsis/root directory expected by scripts/build-setup.py. Update only that script core SHA gate to the actual core binary. Invoke build-setup.py with explicit --payload, --output and --uninstaller absolute paths; it first invokes the actual product Rust verify_package gate and then NSIS. An unrelated signing key cannot pass the fixed product public key gate. No private key is included or generated by this source package.

Online update manifests additionally require the actual GitHub Release ID and asset ID/bytes/hash, sequence1794300003 and the published original issuer signature. They cannot be completed offline before allocating the actual release assets. Do not reuse stale BUILD-IDENTITY, signatures or approved peer hashes with newly compiled binaries.
