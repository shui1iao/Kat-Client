# SS UDP：监听地址族与实用空闲策略（开发候选，未部署）

本变更不增加JSON字段。使用已有`limits.udp_idle`；省略时仍为60秒。替代配置可显式填写`"udp_idle":"5m"`，其它协议的默认值不变。

## 监听
SS原生UDP按配置`inbounds[].listen`中的IP选择地址族，不再根据TCP实际通配绑定结果推断。`0.0.0.0`与明确IPv4使用udp4；显式IPv6使用IPv6-only udp6。UDP端口仍使用TCP实际分配的端口，包括配置`:0`。没有改变TCP自身监听语义或宿主网络参数。

## 原生SS的双向空闲模型
- 完整通过AEAD/格式/时间戳/重放校验的客户端入包续期关联；时间取认证提交时刻，并发旧读者不得把最近活动时间倒退。
- 只有此前已授权、尚未到期的精确目标IP:port的合法大小回包，才可以续期该目标和关联。未知、过期、超大来源不续期、不新增目标授权；不是full-cone。
- 一个目标或客户端方向持续合法活动可以使关联超过创建后5分钟仍工作；是“最后合法活动后5分钟”，不是“每5分钟断开”。其它目标独立过期，不能由无关目标活动复活。
- 空闲到期由既有读超时/有界ticker取消并回收出站socket、关联表、UDP slots与队列。队列及目标数/字节预算不变。回包按最新认证peer，保留0.5.20并发迁移期间可能短暂旧listener回包的已知语义。

## SS2022会话状态与报文安全解耦
内核把同一`udp_idle`传入内部SS codec；会话/回包能力按双向合法活动保留。codec会话保留时间至少61秒，以保护小于该值的关联配置下仍可能落在时间戳窗口内的重放状态；5分钟配置实际使用5分钟，不再由旧61秒回包过期统一截断。保护缓存沿用有界容量及惰性到期清理，在后续codec操作/Stats中清理；它不是仍存活的出站socket或UDP关联。

回包使用当前时间戳和持续唯一的server packet-ID；合法目标回包也续期codec状态。客户端每个包仍必须通过原AEAD、格式、±30秒时间戳和1024包重放窗口检查。延长session状态不使旧报文有效，坏认证/过期报文/重放不能续期、迁移peer或新建关联。counter溢出失败、容量拒绝保持。

没有更改共享`replayTTL`常量：TCP盐与SS2017盐保护仍按原61秒策略；没有改SOCKS/Trojan/AnyTLS的目标续期行为、默认时长或协议。

## 验证范围
针对性normal/race覆盖：IPv4通配及明确IPv4的SS2017/SS2022收发、真实IPv6及V6ONLY、端口0一致性；三种SS2022方法fake clock下70秒和多次活动后的回包/当前时间戳、无活动到期、新认证/迁移、旧capability失效、重放/过期/坏AEAD不变，以及容量/nonce并发和socket/slot/FD回收。

没有等待真实5分钟，没有承载/吞吐矩阵，没有替换现网二进制或旧SS/AnyTLS服务。精确设备/用户客户端生产接入不由这些开发回归自动证明。
